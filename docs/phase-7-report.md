# Rapport de phase 7 — comptes et administration

Livré localement le 29 octobre 2026. Inscription, connexion/déconnexion, profil, changement et réinitialisation du mot de passe, historique/quotas privés et administration sont implémentés sans retirer le parcours visiteur. Même origine, session Laravel et CSRF ; aucun bearer token ni Sanctum nécessaire.

Migration additive `2026_10_29_000005_add_accounts_settings_and_audit` créée et **appliquée à SQLite locale**, six migrations au total. Ajoute users.role/plan, tool_settings et audit_logs. Aucun compte administrateur par défaut ni mot de passe créé. Le premier admin est attribué à un compte existant par `php artisan accounts:admin adresse-du-compte`, action auditée ; révocation par --revoke.

Fichiers : AccountController/AccountRequest, AdminController/AdminSettingsRequest, modèles User/ToolSetting/AuditLog, AccountResetPassword/AccountMail, Settings, routes/accounts.php, Gate/limiteurs/AuthenticateSession, commande accounts:admin, pages React Account/Admin et navigation. Quotas dynamiques validés sous mutex et audit atomique ; activation des outils sous réserve de vérifications, jamais de commande système ou de domaine libre. Statistiques et métadonnées uniquement ; aucun privilège de téléchargement de fichiers tiers pour les admins.

Tests AccountTest (cinq) et AdminTest (quatre) réussis : authentification, hash, longueurs/types invalides, profil, throttling, refus des rôles/plans auto-attribués, reset à usage unique sans token journalisé, permissions, rollback des réglages invalides, audit, rôle CLI et accès aux fichiers tiers refusé. PipelineTest continue de valider les comptes/propriétaires et quotas existants. Le parcours HTTP réel AccountFlowTest (17 assertions) couvre cookies, vrai CSRF, inscription, quota de rôle, conversion via worker séparé, résultat ouvrable, isolation tiers, administration, modification de réglage, suppression, déconnexion et reconnexion. Tests React de connexion, refus admin visiteur et réglages admin réussis.

Le SMTP réel n’est pas configuré/testé : les notifications sont simulées ; en local, l’endpoint de reset retourne MAIL_UNAVAILABLE plutôt que d’écrire un token dans un log. Le lien email utilise un fragment navigateur et l’URL canonique configurée. Les tâches visiteurs ne sont pas transférées automatiquement aux comptes. Vérification email facultative non imposée. Les rétentions exigent le scheduler. Détails : [accounts-and-plans.md](accounts-and-plans.md).
